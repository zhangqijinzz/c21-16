# LatencyLab

本地前端请求链路预算实验室。这里的推演是可重复的时间估算，不会调用真实接口。

## 本地运行

- 运行时：Node.js `>=20 <21`
- 安装依赖：`npm ci`
- 开发预览：`npm run dev`
- 质量门：`npm run lint`、`npm run test`、`npm run typecheck`、`npm run build`

## 功能模块

1. 链路项目：新建、改名、切换与复制项目。
2. 请求编排：增删节点、设置依赖及耗时、超时、重试、失败和降级参数；依赖变成环时拒绝连线。
3. 时序推演：乐观、预期、保守三种波动假设；不限并发或设置并发上限；展示完成预算、排队等待和关键链路。
4. 方案对比：保存当前图和计算结果，比较两份参数快照并恢复任一快照。
5. 本地项目区：管理、复制和删除项目，查看保存状态。

## 架构

`views` 只渲染状态并转发事件。功能 VM 将项目、节点、推演和方案用例分开编排；纯规则位于 `shared/domain`；Repository 依赖 IndexedDB Service，并写入版本化 localStorage 恢复副本。项目数据不会发到服务器。

### 多标签页并发写入保护

两个标签页同时编辑同一工作区时，后保存的一方不会再静默覆盖另一方：

- **修订号 + 乐观并发（CAS）**：落盘数据是 `{ envelope: 2, revision, document }` 信封。IndexedDB 在同一个 readwrite 事务内比对修订号，过期写入主动 abort；localStorage 镜像只在确认提交成功后写入，冲突时绝不动镜像。旧版裸文档按内容指纹获得确定性修订号，首个保存的标签页自动升级且不会误报冲突。
- **写入前三路合并**（`shared/domain/merge.ts`）：以本标签页上次确认版本为共同祖先（base / local / remote）。不同字段、不同项目、不同节点、双方各自新增的依赖边（取并集）等可解释改动自动合并；同一字段双方都改、一改一删才生成冲突条目；合并结果会裁掉指向已删除节点的连线，并在出现循环依赖时给出提示。
- **冲突面板（非模态）**：逐条展示两侧取值，支持逐项“保留本页 / 采用对端”，另有“放弃本页改动”和需要二次确认的“用我的覆盖”。
- **确定的场景行为**：
  - 切换标签页 / 页面重新可见 / 窗口重新聚焦 → 主动探测远端修订号：无本地改动时静默跟随；有改动且不冲突时立即自动合并并保存；真撞车才弹冲突面板。
  - 长时间停在旧页面后再编辑 → 保存携带旧修订号，由 CAS 拒绝并进入同一条合并流程。
  - 冲突面板打开期间继续编辑 → 编辑正常生效并实时并入冲突上下文，但覆盖式保存被暂停直到冲突解决；未处理完就关闭/刷新页面会触发 beforeunload 二次确认。
  - 跨标签页通知走 BroadcastChannel、storage 事件兜底；通知只触发探测，是否冲突一律以存储修订号为准。

默认示例：会话校验和功能开关并发启动；资料与目录在会话后开始；个性推荐等待功能开关和资料。结果使用确定性预算：延迟波动取所选情境、超时截断单次耗时、失败概率决定重试次数期望，重试退避按 200ms 指数增长并封顶 2 秒。降级耗时按最终失败概率加权。并发上限使用稳定拓扑顺序做资源排队估算。
