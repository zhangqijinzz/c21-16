# LatencyLab

本地前端请求链路预算实验室。这里的推演是可重复的时间估算，不会调用真实接口。

## 本地运行

- 运行时：Node.js `>=20 <21`
- 安装依赖：`npm ci`
- 开发预览：`npm run dev`
- 质量门：`npm run lint`、`npm run test`、`npm run typecheck`、`npm run build`

## 功能模块

1. 链路项目：新建、改名、切换与复制项目。
2. 请求编排：增删节点、设置依赖及耗时、超时、重试、失败和降级参数；依赖变成环时拒绝连线。
3. 时序推演：乐观、预期、保守三种波动假设；不限并发或设置并发上限；展示完成预算、排队等待和关键链路。
4. 方案对比：保存当前图和计算结果，比较两份参数快照并恢复任一快照。
5. 本地项目区：管理、复制和删除项目，查看保存状态。

## 架构

`views` 只渲染状态并转发事件。功能 VM 将项目、节点、推演和方案用例分开编排；纯规则位于 `shared/domain`；Repository 依赖 IndexedDB Service，并写入版本化 localStorage 恢复副本。项目数据不会发到服务器。

### 多标签页并发保护

同一工作区在多个标签页打开时，靠三层机制避免“后保存整份覆盖先保存”：

1. **乐观并发（CAS）**：工作区带单调递增的 `revision`。IndexedDB 的
   `conditionalWrite` 在单个 readwrite 事务内比对 revision，只有与本标签页
   已知版本一致才提交，否则中止并返回对方写入的最新文档。旧版数据按
   revision 0 迁移；空库首次写入用 `null` 期望占位，两个标签页不会同时首写成功。
2. **三方合并**：纯函数 `shared/domain/merge.ts` 以“共同祖先 + 我方 + 对方”
   做 3-way merge。项目、节点按实体合并，节点字段（耗时、依赖、降级等）
   按字段合并；两侧改动不重叠时自动合并并给出可解释清单，只有双方改了
   同一字段、或一方删除而另一方修改同一实体时才产生冲突，由用户逐处二选一。
   方案快照不可变，只做新增并集 / 删除。
3. **跨标签页感知**：`WorkspaceSync` 组合 BroadcastChannel（保存后即时通知）、
   `storage` 事件、`visibilitychange` / `focus`（切回标签页立即检查）和定时
   轮询（错过事件的兜底）。干净页面直接载入新版本；本地有未保存改动时立即
   弹出冲突对话框，不必等到保存失败。

确定行为：

- **切换标签页回来**：页面无改动 → 自动载入另一标签页的新版本并提示；有改动 → 进入冲突处理。
- **长时间停在旧页面后再编辑**：远端检查（事件/轮询）先发现新版本，有本地
  改动则进入冲突；此后保存一律被 CAS 拦截，不会覆盖对方。
- **冲突对话框出现时继续编辑**：对话框不关闭，合并预览基于最新草稿实时重算，
  新改的字段自动纳入；对方又保存了新版本时远端侧自动刷新。
- 冲突期间自动保存暂停。可“合并并保存”、“重新载入（放弃本侧改动）”，
  也可暂时关闭对话框（顶部保留冲突横幅，保存状态显示“保存冲突”）。
- 冲突出现时本地草稿写入 localStorage（`conflictDraft`），刷新或崩溃后重开
  页面会恢复草稿；若期间远端又有新版本则继续走三方合并。

默认示例：会话校验和功能开关并发启动；资料与目录在会话后开始；个性推荐等待功能开关和资料。结果使用确定性预算：延迟波动取所选情境、超时截断单次耗时、失败概率决定重试次数期望，重试退避按 200ms 指数增长并封顶 2 秒。降级耗时按最终失败概率加权。并发上限使用稳定拓扑顺序做资源排队估算。
